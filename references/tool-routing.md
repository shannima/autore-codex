# Tool selection

先从文件头、元数据和用户指定环境选方法，再确认工具是否存在。表中的工具是候选，不是依赖清单；本 Skill 的两个 CLI 仅需要 Python 3.8+ 标准库。

| 目标/问题 | 首先读取 | 优先候选 | 无该工具时 |
| --- | --- | --- | --- |
| 原生 PE/ELF/Mach-O | 文件头、架构、导入/导出、字符串 | IDA、Ghidra、radare2 任一 | 先做文件身份与可用静态解析，记录反编译缺口 |
| 托管 .NET | CLR 元数据、程序集引用 | ILSpy、dnSpy、已安装 .NET 工具 | 不把原生 IAT 当作完整业务依赖 |
| APK | Manifest、DEX、native libraries | jadx、apktool；动态需 adb/Frida | 先 ZIP/静态清单，按线索再进入 Java 或 native |
| 运行时解包/行为 | 启动链、子进程、模块映射 | x64dbg、GDB/LLDB、Frida | 先保留静态证据和调试需求，不虚构 dump |
| 本地协议重建 | 已提供流量、调用顺序、编码/字段 | Wireshark、离线解析脚本 | 标明缺失请求/响应，不猜成已证实字段 |
| JS/WASM 样本 | 模块入口、调用链、输入输出 | 浏览器调试器、Node、本机专项技能 | 先离线读取代码；记录运行环境差异 |
| GUI 结果证明 | PID、class、title、功能状态 | 可用截图/UI 自动化工具 | 保留日志并明确缺少视觉证明 |

若环境已提供 `reverse-skill` 或专项技能，可只读取当前问题匹配的模块；本仓库不携带也不依赖其整套路由、自举或服务。避免一次加载所有参考文档。

将实际工具版本、可执行路径和参数写入运行记录。服务端口必须从本次配置/工具发现结果读取，不能假定 `127.0.0.1:13337` 等端口可用。工具缺失时优先使用已安装替代工具；需要安装时说明准确包名、来源和作用范围，不自动执行外部仓库安装器。
