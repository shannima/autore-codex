## 2. 分仓库判断

### gpt-instruct

值得复用的是工程方法：先明确输出工件，再验证其存在、内容和复现能力；对未运行的评测如实标记，避免用不同条件的分数互相替代。AutoRE 将此转为脚本自动测试、案件证据检查和手工行为场景三层，不照搬其 A/B/C 样例或模型成绩。

其全局模型指令部署与 AutoRE 的任务级 Skill 不属于同一层。将整套提示词叠加入口会增加上下文和冲突维护成本，因此保留模型无关的任务契约，不写模型身份、激活口令或声称改变模型权限的指令。

### gpt6-Astra

读取的 `seats.py` 有客户端别名、路径解析、部署、备份、验证与恢复分工；README 提供了明确的客户端写入范围。AutoRE 借鉴“变更有边界、恢复有依据”，落实为初始化预览、保留已有文件、逐轮修改与恢复记录。

该快照中中文 README 标注 3.1.0-preview.3 和 11 个客户端，而英文 README 仍出现 2.3.6 与较旧数量；`seats.py` 的 PACK_IDS 也不等同于中文桌面表。不能把一个入口或宣传页面当作所有实现的能力证明。AutoRE 因而保持一套入口文档，并分别说明脚本检查和实际行为验证的范围。

本次不复制其客户端注入器、桌面应用、口令、模型指令包或中转服务配置；这些不解决 AutoRE 的案件证据问题。

### reverse-skill

其专业模块路由、按需工具选择、阶段交接与 Evidence→Finding→Path 提供了更完整的案件组织方式。对 AutoRE 最直接的价值是：把观察、推断和决策分开；地址绑定具体镜像；阶段切换只携带增量和证据引用；工具存在性必须实际确认。

整套模块、自举和服务会显著扩大本仓库维护面。本次用小型工具选择表、单写者证据索引和报告中的 Finding→Evidence 引用实现需要的部分。工具缺失时给替代路径；不硬编码机器路径或默认服务端口，也不要求安装 reverse-skill。

## 3. 原仓库问题与落地

| 原有情况 | 本次实现 | 可检查结果 |
| --- | --- | --- |
| 动态单点控制已有文字约束，但交接状态不明确 | 增补控制权交接字段与共享文件单写者规则 | 角色文档及手工评估场景 |
| 初始化只有 README/writeup 与四个目录 | 增加 case.json、STATE.md、evidence.json、runs/ | CLI 初始化测试 |
| 目标不存在仍继续创建目录 | 输入与已有路径先校验 | 无效目标不会留下新案件目录 |
| 复用时无机器可检查的目标身份 | 样本大小/SHA256/路径一致性检查 | 不同目标拒绝混入 |
| 日志/截图无法机器检查完整性 | record/check 工具 | 丢失、越界、重复 ID、哈希变化测试 |
| 模板外层代码围栏与内部围栏冲突 | 外层四反引号 | Markdown 结构可阅读 |
| 没有回归验证 | unittest 和双系统 CI 配置 | 实际测试结果，非模型解题通过率 |

## 4. 取舍和后续维护

本次实现由本仓库新写，未复制上游提示词、程序实现或素材；保留固定提交链接便于核对设计来源，没有替仓库作者新选许可证。若未来复制第三方代码或素材，应逐文件保留相应许可和版权声明。

证据索引是轻量文件格式，没有数据库锁、数字签名或自动语义判定；适合单控制者、本地受控案件。暂不增加 GUI、全局配置安装器、自动工具下载、全量技能包或宣称支持所有客户端。

后续应根据真实案件失败增加回归场景：记录当时的目标、输入、输出、工具环境和失败原因，再修改规则。不要将个别样本的地址、端口、固定时长或补丁策略写成所有案件必须遵循的步骤。
